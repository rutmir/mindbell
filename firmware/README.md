# MindBell — прошивка (ESP32-C3, Rust)

Носимая вибро-«напоминалка». Логику и схемотехнику см. в `../hardware_notes.md`.

## Что делает прошивка

Машина состояний вокруг deep sleep:

| Событие пробуждения | Действие |
|---|---|
| **Таймер RTC** | проснулись ровно к слоту расписания → виброимпульс → снова сон |
| **Кнопка (долгое нажатие ≥2 с)** | виброподтверждение → поднять BLE на 30 с (или до отключения телефона) → принять время/расписание → сон |
| **Кнопка (короткое нажатие)** | игнорируется, сразу обратно в сон (защита от случайных нажатий) |
| **Холодный старт (первое включение / потеря питания)** | если время не выставлено — сразу BLE для синхронизации |

Физического выключателя нет: «есть питание = работает». В режим настройки
заходим **долгим нажатием отдельной кнопки** (GPIO4). Время суток ведут
системные часы и переживают deep sleep, так что при входе в настройку оно НЕ
сбрасывается (синхронизировать заново нужно только после полной потери питания).
Встроенные BOOT/RST для этого не используются.

- Расписание — массив диапазонов `{start_min, end_min, interval_min, enabled}`,
  хранится в NVS, переживает сон/перезагрузку.
- Время суток ведут системные часы (ESP-IDF сохраняет их через deep sleep).
  Дата не нужна — расписание оперирует только временем суток; телефон шлёт
  «локальный epoch» (UTC + смещение зоны).
- Логика расписания (`src/schedule.rs`) — чистый Rust, покрыта юнит-тестами.

## ⚠️ Перед сборкой — проверьте пины

В `src/main.rs` заданы по умолчанию:

| Назначение | Пин | Требование |
|---|---|---|
| Питание | `3V3` + `G` | с выхода LDO 3.3 В |
| Затвор MOSFET мотора | `GPIO3` | внешний pulldown Rpd (мотор выключен в сне) |
| Кнопка настройки | `GPIO4` | **только GPIO0..5** (будят C3 из deep sleep); кнопка на GND + внешний pull-up 80 кОм на 3V3 |

Замер заряда батареи в прошивке **отключён** (делитель не разведён). Схему для
будущего добавления см. в `../hardware_notes.md` §5. Если меняете пины — правьте
`peripherals.pins.gpio3` (мотор) / `gpio4` + `BUTTON_GPIO_NUM` (кнопка) в `main.rs`.

## Установка тулчейна (один раз)

ESP-IDF + Rust ставятся через `espup`:

```bash
cargo install espup espflash ldproxy
espup install
# Подгрузить переменные окружения (делать в каждом новом терминале,
# либо добавить в ~/.bashrc):
. $HOME/export-esp.sh
```

Также нужны системные пакеты для сборки ESP-IDF: `git`, `cmake`, `ninja`,
`python3`, `libusb`. На Fedora/Qubes:

```bash
sudo dnf install git cmake ninja-build python3 python3-pip libusb1
```

Первая сборка скачает ESP-IDF v5.2.2 и тулчейн — это долго (сотни МБ). Дальше
из кэша.

## Сборка и прошивка

```bash
cd firmware

# Юнит-тесты логики расписания (на хосте, без железа):
cargo test --target x86_64-unknown-linux-gnu -p mindbell schedule

# Сборка прошивки:
cargo build --release

# Прошить + открыть монитор (runner уже настроен в .cargo/config.toml):
cargo run --release
```

Если порт не определился сам — укажите явно:

```bash
espflash flash --monitor --port /dev/ttyACM0 target/riscv32imc-esp-espidf/release/mindbell
```

Большинство плат ESP32-C3 прошиваются по USB-C автоматически. Если нет —
введите режим загрузки: зажать **BOOT (GPIO9)**, коротко нажать **RESET**,
отпустить BOOT.

> Внимание: для прошивки плата подключается к USB. Тот же USB-C, через который
> заряжается аккумулятор (TP4056), как правило **не** соединён с USB-портом
> самого ESP32 — это разные разъёмы/линии. Прошивайте через USB-порт платы.

## Проверка после прошивки

1. В мониторе видно `cold boot` → `time not set -> config mode for sync` и
   `advertising as 'MindBell'`.
2. С телефона (nRF Connect или ваше Flutter-приложение) подключитесь к
   `MindBell`, найдите сервис `6d696e64-…-0000`:
   - запишите в характеристику **…0003** время (u64 LE, локальный epoch);
   - запишите в **…0001** расписание (JSON, см. ниже).
3. Устройство уйдёт в сон и начнёт вибрировать по расписанию. Долгое нажатие
   кнопки (≥2 с) — снова режим настройки.

## Формат расписания (JSON)

```json
{
  "segments": [
    { "start_min": 540,  "end_min": 1200, "interval_min": 7,  "enabled": true },
    { "start_min": 1200, "end_min": 1380, "interval_min": 20, "enabled": true }
  ]
}
```

`start_min`/`end_min` — минуты от полуночи (9:00 = 540, 20:00 = 1200, 23:00 =
1380). Диапазон не должен пересекать полночь; ночную тишину задавайте «дыркой»
между диапазонами. Слоты выровнены по началу диапазона (9:00, 9:07, 9:14, …).

## UUID для приложения

| Назначение | UUID | Формат |
|---|---|---|
| Сервис | `6d696e64-6265-6c6c-0000-000000000000` | — |
| Расписание (R/W) | `…0001` | JSON UTF-8 |
| Время (W) | `…0003` | u64 LE, локальный epoch (сек) |

(UUID `…0002` зарезервирован под батарею на будущее — сейчас не используется.)

## Замер тока покоя (из TODO в hardware_notes.md)

После прошивки и ухода в сон разорвите цепь питания и включите туда
мультиметр в режиме мА/мкА. Цель — единицы мкА (плюс ток LDO). Если видите
миллиамперы — что-то держит устройство в активном режиме (или мешает MT3608,
если он ещё не выпаян).
