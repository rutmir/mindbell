# Проверка изменений прошивки MindBell

Железо из этой машины недоступно: прошивают с Omega (Ubuntu), в Qubes
USB-JTAG ломается при ре-энумерации; QEMU для ESP32 не установлен.

## Что работает

- **Сборка под таргет** (единственная полная компиляция main.rs):
  `cd firmware && cargo build --release` (~5 мин, тулчейн nightly-2025-03-15).
- **Юнит-тесты schedule.rs**: команда из README
  (`cargo test --target x86_64-unknown-linux-gnu`) НЕ работает — build-скрипт
  esp-idf-sys отвергает x86_64. Вместо этого: хост-крейт-обёртка, подключающий
  `firmware/src/schedule.rs` через `#[path]` (зависимости: serde+derive,
  serde_json, anyhow).
- **Поведенческая проверка** (дубли/пропуски слотов, дрейф, синки): симулятор
  «истинное время vs дрейфующий RC» в том же хост-крейте — реальный
  schedule.rs + дословная реплика арифметики main.rs
  (apply_drift_correction / on_time_sync / предкомпенсация сна / guard).
  Образец лежал в scratchpad сессии 2026-07-10 (schedtest); при необходимости
  воссоздать: модель — таймер deep sleep считает в «сырых» единицах устройства,
  device_rate = 1 + ppm/1e6, синки от телефона дают истинный UTC.

## Гочи

- Реплики формул main.rs надо сверять с дифом дословно — иначе проверяется не то.
- corr в apply_drift_correction применяется целыми секундами, дробный остаток
  переносится через CORR_REMAINDER (RTC-память); cal_ppm сходится к p/(1+p)
  (для +7000 ppm — 6951), уход от истинного времени между синками — секунды.
  Если в симуляции cal_ppm завышен на ~5–7% и уход минуты — остаток потерялся.
- Финальная валидация — только на устройстве с Omega: лог
  `entering deep sleep for N s (raw M us, cal_ppm=K, ...)` и `wakeup: ...`.
